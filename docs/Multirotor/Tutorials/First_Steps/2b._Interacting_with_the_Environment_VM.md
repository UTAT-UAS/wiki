## Virtual Machine

Create a virtual machine with the VMM of your choice, and install a Ubuntu 24.04 (native to your host CPU) on the VM. You will need to configure the network interface your host and VM instance can share. Most VMMs have the network interface shared between host and the VM by default.

??? note "QEMU NAT interface"
    QEMU NAT is purely userspace and doesn't expose an network interface to the host. For the purpose of the setup, you will need to also enable host-only or bridge networking.


## The Simulation

> We assume you don't want to use X11 to forward simulation in this setup since the simulation uses GPU and GPU passthrough is complicated if the host OS is different from the VM OS.

Install PX4 and ROS2 in your VM. Use the package manager or compile them from source. The previous tutorial introduces about some basic way to interact with the Ubuntu package manager.

Install Gazebo and QGroundControl on your Host. Download the binary package from the internet and install them.

Since Gazebo server and client can run separately, we can start gazebo as a server on VM, and client on the Host so Gazebo render using GPU directly on host.

Before we run the next command, make sure you also copy any PX4 `gz_x500` models onto your host so the Gazebo client can find them.

Note that the PX4 guideline uses `make px4_sitl gz_x500`, which internally start both gazebo client and server in the VM. To setup server and client separately, use the following command on your VM to start the server.

```bash
/usr/bin/cmake -E env PX4_SIM_MODEL=gz_x500 GZ_IP=<IP_OF_THE_VM> GZ_PARTITION=1 GZ_VERBOSE=1 GZ_TRANSPORT_RCVHWM=100000 GZ_TRANSPORT_SNDHWM=100000 GZ_TRANSPORT_TOPIC_STATISTICS=0 /path/to/PX4-Autopilot/build/px4_sitl_default/bin/px4
```

And use the following command on your host to start the client
```bash
# at /path/to/px4/model
GZ_IP=<IP_OF_THE_HOST> GZ_PARTITION=1 GZ_RELAY=<IP_OF_THE_HOST> GZ_VERBOSE=1 GZ_TRANSPORT_RCVHWM=100000 GZ_TRANSPORT_SNDHWM=100000 GZ_TRANSPORT_TOPIC_STATISTICS=0 gz sim -g -v4 x500/model.sdf
```

You might encouter issues with QGroundControl not receiving mavlink traffic from PX4 in the VM. If this is the case, check the local UDP port of mavlink using the following command in the PX4 console
```
mavlink status
```

And add a remote udp link in your gazebo under Settings > Comm Links, with the network address mavlink (i.e. the IP address of the VM + the port of UDP mavlink) is on.
