    Developer Environment (Software Tools)

    Docker🔗

    To use GPU for flight simulation on non-Linux host, it's recommended to set up your development environment in a virtual machine.

    Docker can be installed here (click on Ubuntu): https://docs.docker.com/engine/install/

    You will want to add yourself to the docker group: https://docs.docker.com/engine/install/linux-postinstall/

    If you'd like to use Docker Desktop (easiest way to install on Windows and Mac):

    For WSL2 see here: https://docs.docker.com/desktop/setup/install/windows-install/

    For Mac see here: https://docs.docker.com/desktop/setup/install/mac-install/

    For Linux see here: https://docs.docker.com/desktop/setup/install/linux/

    Virtual Machine Manager (VMM)🔗

    A virtual machine manager is a software that enables you to run another operating system (of different kernels) on your host. Below are a list of virtual machine monitor we recommended. Create a Linux VM on your host using a VMM you like.

    Note that WSL2, Libvirt and QEMU are command line driven. If you haven't used any VMM before, you will likely find it easier to start with a desktop-friendly VMM such as VirtualBox or VMware.

    Virtual Machine Monitor Supported Platforms Link / Installation Command
    Virtual Box Linux (x64), Windows (arm64, x64), MacOS (arm64, x64) https://www.virtualbox.org/wiki/Downloads/
    VMware Workstation Linux (x64), Windows (x64) https://www.vmware.com/products/desktop-hypervisor/workstation-and-fusion
    VMware Fusion MacOS (arm64, x64) https://www.vmware.com/products/desktop-hypervisor/workstation-and-fusion
    WSL2 Windows (arm64, x64) https://learn.microsoft.com/en-us/windows/wsl/install
    Libvirt (backed by QEMU) Linux (x64, arm64), MacOS (arm64, x64) Use your package manager on Linux or MacOS
    QEMU Linux (x64, arm64), MacOS (arm64, x64), Windows (arm64, x64) Use your package manager on Linux or MacOS, or if you are on Windows check https://www.qemu.org/download/#windows

    Git🔗

    At its core Git allows us to create "repositories" that tracks all files you tell it to. You "save" the repository by creating commits which contain the differences in text between the previous commit and your changes. This process of storing differences (or "diffs") allows the history of a codebase to be tracked and changes made readily apparent.

    These tutorials will describe how to work with git from the command line. There are GUI (Graphical User Interface) programs to work with git as well, but they will not be covered here.

    You can install Git here (click on your OS): https://git-scm.com/downloads

    We will go over Git as we need it, but if you have no experience and would like to do some pre-reading these are some good places to start:

    • https://learngitbranching.js.org/
    • https://www.w3schools.com/git/

    VS Code🔗

    VS Code is a popular text editor developed by Microsoft, it is highly extendable with many plugins existing that can turn it into a fully featured integrated development environment (IDE).

    Install VS Code if you haven't already: https://code.visualstudio.com/

    You will need the dev containers extension if you're using Docker, just search for "dev containers" in the extension tab (Ctrl+Shift+X) or see here: https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers

    If you'd like to learn more about dev containers see here for the full overview: https://code.visualstudio.com/docs/devcontainers/containers

    For VM users, install the Remote - SSH extension. Search for "remote ssh" in the extension tab or see here: https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-ssh-edit

    GitHub🔗

    GitHub is a remote Git repository host also owned by Microsoft, it allows us collaborate on a single Git repository.

    SSH or Secure Shell Protocol is a key based authorization system used to connect to servers and services, and is the recommended way to interact with GitHub.

    You will need to generate some keys: https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent

    Add them to your GitHub account: https://docs.github.com/en/authentication/connecting-to-github-with-ssh/adding-a-new-ssh-key-to-your-github-account

    These tutorials assume you will configure git and GitHub with SSH.

    Environment🔗

    Docker🔗

    Open a terminal in the folder/directory where you store your code.

    Clone the repository with git clone git@github.com:UTAT-UAS/dev_env.git

    https://github.com/UTAT-UAS/dev_env

    Open the newly created dev_env folder with VS Code, you should be prompted by a pop-up in the bottom right to open this folder in a container, click Yes or equivalent.

    If not open command palette ctrl+shift+p and search for Dev Containers: Open Folder in Container.

    Dev Containers will now pull the prebuilt base image from ghcr.io and run some setup commands. This should take a few minutes with fast internet.

    Eventually you should see Done. Press any key to close the terminal.

    Building from source

    The DockerFile is provided in .devcontainer/Dockerfile, do something like docker build dev_env:local .devcontainer to build the image locally. In order to use the image devcontainers is configured to use the docker-compose.yml to create and start the container, edit image for the uas service.
    Note that this will take a long time (~15 to 30++ minutes).

    Building on ARM

    The PX4 version we are using recognized (older version might not) an ARM64 Linux and will build correctly. If you encouter any issues, check if you have any missing or version-mismatched dependencies.

    VM🔗

    There are several ways to install Ubuntu 24.04, but for this guide, download the standard installation image https://ubuntu.com/download/server.

    Create a virtual machine with the VMM of your choice, and install Ubuntu 24.04 (matching your CPU architecture, such as x86_64) on the VM. You will need to configure the network interface the host and VM instance can share.

    QEMU NAT interface

    QEMU NAT is purely user-space and doesn't expose a network interface to the host. For the purpose of the setup, you will need to also enable host-only or bridged networking.

    After installation, you need to configure SSH on your VM so you can access your VM easily. Ensure your environment has a working SSH client and the necessary keys or credentials established.

    Install PX4, ROS2 and Gazebo in your VM (use the same version of the toolchains in the Dockerfile at https://github.com/UTAT-UAS/dev_env). You may use the package manager or build them from source. The next tutorial covers how you can interact with a package manager. Also install Gazebo and QGroundControl on your Host.

    In the next section make sure to follow the VM section when setting up the simulation.
